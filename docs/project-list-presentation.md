# 项目列表：运行优先与视觉分区

## 展示规则

项目列表在过滤后统一排序，适用于全部项目、收藏、自定义分类与搜索结果。显示顺序不回写 `config/projects.json`，也不按内存、PID 或轮询时间排序。

| 优先级 | 状态 | 视觉区域 |
| --- | --- | --- |
| 0 | `running`，不区分 managed / external / adopted / self | 运行与活动项目，极浅绿色行背景 |
| 1 | `starting`、`stopping`、`partial`、`alternate`、`multi_instance` | 运行与活动项目，中性行背景，保留各自状态颜色 |
| 2 | `error`、`conflict` | 未运行项目顶部，保留红色状态 |
| 3 | `stopped`、`unknown` 及未识别状态 | 未运行项目，中性灰标签与次要文字层级 |

同级按收藏优先，再保留配置中的手动顺序。分组标题显示当前过滤结果的数量；空分组不显示。“运行中”分类、状态过滤、计数和行标签使用同一项目展示状态；不把部分运行冒充正常运行。

排序本身只改变展示优先级，不修改进程所有权、启动或停止权限。项目列表不恢复 PID 标签，保留资源汇总和必要的异常详情入口。多实例项目的整体状态另按下述规则聚合。

## 已有实例运行时新增实例

- `allowMultiple=true` 且已有实例仍在运行时，点击“启动新实例”不把项目整体从 `running` 降为 `starting`。项目保持原运行优先级和绿色状态，说明显示“已有实例运行，正在启动新实例”；按钮和独立启动面板继续显示新增实例的进度。
- 即时点击反馈、轮询重绘、排序、筛选及计数统一使用 `projectActionDisplay()`，避免只修排序而标签或运行分类仍闪动。
- 后端运行时增加 `readyCount`：存活、非启动中、非停止中、无 `lastError` 的实例数量；`instances[].starting` 暴露实例启动状态。原 `runningCount` 语义不变，它可能包含尚未确认启动的进程，不能单独作为已有稳定实例的依据。
- 无端口项目在新增实例启动时，只要仍有 `readyCount > 0` 的运行实例或经原有匹配规则确认归属的外部实例，项目整体返回 `running`。端口健康检查及冲突判定不放宽。
- 首次启动、单实例项目、`restart` 和停止操作仍显示原有过渡状态。旧实例全部退出时，不继续保留绿色运行状态。新增实例失败但旧实例仍运行时，失败归属于本次启动面板，不改变旧实例的运行排序。
- 兼容尚未重启的旧后端：前端在点击前记录已运行实例的 `instanceId`；仅当后续状态仍包含该旧实例时保留运行状态，不能仅依据 PID 数量或旧快照。新后端提供 `readyCount` 后以它为准。

部署时刷新页面加载前端修复；后端聚合修正需要重启管理台后端后生效。无需修改任何业务项目源码。本次未为了验证新增或停止真实业务实例。

## 拖拽与动态更新

- 仅允许同一状态优先级、同一收藏层级的可见项目互相排序。跨层级拖拽给出提示，不调用保存接口。
- 保存时只替换当前可见层级在配置序列中占据的位置，保留其他层级及被筛选隐藏项目的位置。
- 拖拽结束前重新核对状态，避免轮询期间项目状态变化造成跨组保存。
- 拖拽、保存顺序或操作确认对话框期间，后台状态可继续更新，但暂缓重建表格 DOM；结束后渲染最新状态。取消确认也会释放延迟更新。
- 确认结束后恢复对应项目控件的键盘焦点；如果控件已随重绘替换，重新定位可用控件。
- 启动进度和日志附件与项目行作为一个展示单元移动，不被分组标题分隔。

## 样式边界

保留现有七列表格、字体和紧凑行密度，新增分组标题及组间隔。正常运行项目以浅绿背景、较强名称字重呈现；未运行项目只降低名称、路径和网址的视觉层级，不使用整行透明度，也不禁用操作按钮。收藏以小星标表达，避免侧边装饰线与运行层级竞争。启动附件的连接背景与所属项目保持一致。

新增文字与背景色的测试组合达到至少 4.5:1 对比度。此项不是全站无障碍认证。
