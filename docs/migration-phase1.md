# 环境迁移第一期

第一期迁移包用于在两台 Windows 电脑之间恢复项目管理台配置和 Git 仓库。`.plwmigrate` 是带 SHA-256 完整性校验的 gzip/tar 归档，内部包含清单和必要的离线 Git Bundle。

## 包含内容

- `projects.json` 的可移植配置快照
- `${PROJECTS_ROOT}` 路径映射
- Git 仓库远端、分支、提交和同步状态
- 没有可靠远端或存在未推送提交时的离线 Git Bundle
- 项目到仓库的相对路径绑定
- 操作系统、Node.js、npm、Python、GitHub CLI、Codex 等环境版本清单

## 明确排除

- 工作区文件副本、`node_modules`、Python 虚拟环境
- `.env`、API Key、登录凭据和 SSH 私钥
- Codex 会话、个人配置和缓存
- 管理台运行状态、PID 和日志

## 导出

1. 点击左侧栏底部弱化显示的“环境迁移”。
2. 等待管理台扫描所有项目和 Git 仓库。
3. 处理所有红色阻止项。存在未提交或未跟踪文件时不能导出。
4. 按仓库勾选是否加入离线 Git Bundle，再点击“生成迁移包”并妥善保存下载的文件。

第一期会扫描疑似密码、Token 和 API Key；检测到敏感内容时会阻止导出，但不会在页面或日志中显示具体值。

GitHub 不是迁移前提：有可靠远端且本地没有领先提交的仓库可从远端恢复，其他干净仓库随迁移包离线恢复。

离线 Bundle 是可选项。没有远端或存在未推送提交时默认勾选，用于保护当前本地提交，但可以手动取消：

- 有可靠上游的仓库取消后，只恢复扫描时确认的上游提交，本地未推送提交不会进入迁移包。
- 没有可靠上游的仓库取消后，恢复方式改为“手动准备”，需自行复制仓库。
- 已与上游同步的仓库默认不勾选，也可以主动勾选以增加一份离线副本。
- 未提交和未跟踪文件不属于 Git Bundle，无论是否勾选都会阻止导出。

勾选只影响本次导出，不写入 `projects.json`。真正生成文件前管理台会重新扫描，并比对预检校验值；仓库提交、同步状态或项目配置发生变化时必须重新扫描。

没有初始化 Git 的目录不能生成 Bundle，会在清单中标记为“手动准备”；导入前需先把该目录复制到目标电脑。

仓库是迁移和去重单元，项目只是仓库引用。同一 PolymarketBots 仓库下的多个策略只生成一个 Bundle、只恢复一次，再通过相对路径关联到各项目。相同远端但本地根目录不同的仓库仍视为两个独立工作副本。

## 导入

1. 在新电脑安装项目管理台并打开“迁移环境”。
2. 选择 `.plwmigrate` 文件。
3. 将 `${PROJECTS_ROOT}` 映射到新电脑的项目根目录。
4. 检查仓库恢复方式、目标路径冲突和环境提醒。
5. 停止所有已登记项目后点击“恢复配置”。管理台先恢复缺失仓库，再写入配置。

恢复前会自动备份当前 `config/projects.json`。已有目标目录不会被覆盖：必须是对应 Git 仓库并包含要求的提交，否则预检会阻止恢复。第一期不会安装依赖或启动项目。
